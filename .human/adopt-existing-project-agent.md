# Инструкция агенту: внедрение workflow в существующий проект

## Цель

Зафиксировать фактический baseline и создать минимальный маршрут для следующей работы через SPEC-MAP, независимые `WI-NNN`, компактный BOARD и checkpoint-only WAL.

## Порядок

1. Изучи инструкции, specs, BOARD/WAL/ROADMAP, код, тесты, runtime и интеграции.
2. Отдели подтверждённое состояние от будущих улучшений и вопросов.
3. Добавь актуальные protocols, `SPEC-MAP.md`, `work/` и локальный `.me.template`.
4. Заполни `common/main.md` и `common/structure.md` по реальному проекту.
5. Зарегистрируй существующие спеки с lifecycle и краткой responsibility.
6. Применяй WI и checkpoint-only WAL ко всей новой отслеживаемой работе.

## Forward-only migration

- Сохраняй legacy IDs, `.A/.B/.C` серии и полезные ссылки.
- Не создавай WI задним числом для каждого завершённого документа.
- Переноси историю BOARD/WAL в Git или отдельный snapshot, когда активные файлы требуют компактности.
- Lifecycle добавляй при содержательном изменении; legacy документ без YAML до migration считается active.
- Массовая замена legacy `@spec` требует отдельного WI и не входит в adoption автоматически.

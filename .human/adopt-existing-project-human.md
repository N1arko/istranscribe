# Как встроен workflow в существующий проект

`specs/` хранит общий канон и управляемое состояние работы. Спеки описывают систему, WI проводят ограниченные изменения, BOARD показывает очередь, WAL сохраняет только незавершённые checkpoints.

Миграция сохраняет IDs, существующие ссылки и Git-историю. Она не меняет продуктовый код ради структуры документации. Спорные области фиксируются через `REVIEW`, lifecycle или `TECHDEBT`.

После migration новые изменения проходят так:

```text
обновить канон → зарегистрировать в SPEC-MAP → создать WI при необходимости
→ добавить строку в BOARD → выполнить acceptance → archive WI
```
